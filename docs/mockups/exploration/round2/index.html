Round 2 — three information architectures

Round 1 converged on structure and diverged on look, which was backwards. This round fixes the look decisions and tests the three information architectures that were genuinely still open. All three are built mobile-first, hold the same warm palette family, and realize the same core loop so the comparison is honest.

Decisions settled from round 1

Baseline
Mobile-first. Desktop is the optimized version — more shown at once, not a different design.
Item shape
Card on mobile, collapsing to a row with aligned columns on desktop. Same data, two presentations.
Tags
Text #hashtags, differentiated from title/host/note by weight and colour only. No pills on items.
Quick add
A plain form — URL, server-fetched title, tag chips, an explicit visible Add to reading list toggle. Inline #tag / @coll syntax accepted as an optional shortcut, never required.
Navigation
Bottom tabs on mobile (Inbox, Queue, Feeds, Collections, Search), pinned composer above them. Label rail on desktop.
Reading
Deferred. The queue is a list; items open the original in a new tab. No in-app reader in this round.
Feeds
Two lifecycles shown side by side, because the IA choice interacts with it.
Palette
Warm café/mocha held constant across all three, varying only in temperature and saturation.
Depth
Borders + a slight button shadow by default. Each candidate carries a standalone section comparing flat / default / paper-layered.

The candidates

Candidate 1

Cards

round 1's B, densified · no columns ever

The calm direction made denser. Navigation by tabs and sheets rather than a persistent rail, uniform items with real note presence, and the mobile composer as the app's signature gesture.

  • Best for: notes, reading, mobile, calm
  • Weakest for: comparing across many items at once
  • Round 1's complaint answered: whitespace, radius, and sans typography all pulled back.
 Candidate 2

Ledger

round 1's C, mobile-first

The ledger taken seriously as a mobile structure rather than a desktop one. Columns collapse into a card on small screens and return as the width grows; the rail becomes a bottom tab bar.

  • Best for: retrieval, organization, scanning many items
  • Weakest for: long notes, which have to compress into a sub-line
  • Round 1's complaint answered: the note-count column is gone, notes are always visible as text.
 Candidate 3

Split Sheet

round 1's A, rebuilt mobile-first

The inspector idea kept, but the two-pane desktop layout abandoned. Selection opens a bottom sheet on mobile; the right pane is only a bonus at desktop widths. Permanent visible actions, keyboard-first, dense rows.

  • Best for: triage, bulk operations, power use
  • Weakest for: casual discovery — actions are hidden until you select
  • Round 1's complaint answered: the desktop-primary framing is gone; mobile is the whole design.
