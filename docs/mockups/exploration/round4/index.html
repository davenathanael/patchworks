Round 4 — the final round

The design is settled. This round finalises the fonts, applies the two accessibility and robustness fixes identified at the end of round 3, and adds the component and state reference that was missing — a document you can hand to implementation without re-reading the whole app mockup.

What changed in round 4

ChangeDetail
Focus statesEvery focusable element gets a 2px ring plus its native affordance, wired with :focus-visible so it never appears on mouse click. Fields additionally get an accent border and a 3px halo. The ring is a fixed blue in both themes rather than the accent — it has to read as "you are here" across two palettes and both themes, and stay visible on top of the accent fill. A skip link is the first child of every app region.
Error statesFour layers, each with a defined job: .ferr for a single invalid field, .alert for a region-level failure, .toast for transient notifications, and .rowfail for one item inside a list. All four carry a glyph and a word, never colour alone. A destructive failure never uses a toast alone.
Fonts finalisedFraunces for display only, Source Serif 4 for all prose, Geist for chrome, Geist Mono (Sepia) or JetBrains Mono (Mocha) for metadata. Two skins retained: Sepia as default, Mocha as the warmer option.
Component referenceTen sections covering typography, buttons, form controls, tags and badges, navigation, alerts, toasts, overlays, empty/loading/error, and data display — with the frozen-state technique for hover and focus.

Settled design decisions

Baseline
Mobile-first. Desktop shows more of the same thing, never a different design. Item is a card on mobile and a row past 54rem.
Type
Fraunces (display) · Source Serif 4 (prose) · Geist (chrome) · Geist Mono or JetBrains Mono (metadata).
Long notes
Four-line excerpt in the list, expanding in place. The note editor lives in the inspection sheet as a real textarea.
Inspection
Bottom sheet on mobile with a top-edge shadow; docked side pane at 54rem and up.
Tags
Plain #hashtags on items. Small neutral pills in pickers, with a dashed border reserved for "creates something new".
Collections
Separate display title and @handle, both editable.
Quick add
One <dialog>: full-screen on mobile, centred popover on desktop, header inside the panel.
Reading
No in-app reader. The queue is a list; current item pinned to top; items open the original in a new tab.
Feeds
Path A. Feed items are ephemeral until acted on: added to the queue, saved as a bookmark, or dismissed.
Share page
Public, read-only, one page per collection. Every bookmark with its tags and notes, regardless of your own reading or queue state.
Account
Fifth tab (Inbox, Queue, Feeds, Collections, You) on mobile; avatar menu in the top strip on desktop.
Depth
Borders plus a button shadow. Floating surfaces get a real shadow. Nothing else is elevated.
Wide screens
Cap the width, grow the type. No extra columns, no docked panels.
Themes
Sepia and Mocha, each in light and dark. Dark backgrounds sit at oklch L≈0.27 rather than the usual 0.18–0.20; body text measures 13:1 against the background, secondary 8:1, muted metadata 5.5:1.

Known gaps, carried forward

Note commit pathAutosave on blur or explicit save is still undecided. The sheet currently shows a textarea with no commit control.
Filter & sortRound 3 dropped the filter sheet in favour of query syntax. Sorting has no equivalent at all. Probably a convergence accident rather than a decision.
Long-title overflowNo truncation rule or max-height has been tested against a 120-character title.
"Show note" vs sheetTwo routes to the same content with different affordances. One should probably go.
Safe-area insetsBottom tabs and the composer need env(safe-area-inset-bottom) on iOS.
No-JS quick addThe round-1 constraint that quick-add works without scripting has not been re-verified against the <dialog> approach.
Bulk selectionDropped in the convergence. Deliberately, or lost — worth confirming.
Archived viewPresent in desktop navigation, never designed.
